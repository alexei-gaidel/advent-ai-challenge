# 17 — Первый инструмент MCP

**Задание:** реализовать свой MCP-сервер вокруг любого API — с регистрацией инструмента,
описанием входных параметров и возвратом результата. Подключить инструмент к агенту,
вызвать его из приложения и использовать результат.

## Запуск

```bash
cd 17-mcp-tool
python3 git_server.py --selftest   # инструменты сервера без клиента
python3 tool_demo.py               # сравнение: агент с инструментами и без
python3 web.py                     # агент на http://localhost:8017
python3 make_cast.py               # пересобрать demo.svg
```

Зависимостей нет: сервер, клиент и агент — стандартная библиотека.

## Что обёрнуто

API — **git этого же репозитория**. Выбор не случайный: ключей не нужно, результат
проверяется глазами, а агент получает способность отвечать про историю челленджа
фактами, а не по памяти модели.

Четыре инструмента:

| Инструмент | Аргументы | Что делает |
|---|---|---|
| `git_log` | `limit`, `grep`, `path` | история коммитов, можно искать по тексту сообщения и по папке |
| `git_show` | `ref`* | подробности коммита: автор, дата, сообщение, изменённые файлы |
| `git_search` | `query`*, `path`, `limit` | поиск строки в содержимом файлов |
| `git_summary` | — | сводка: коммитов, папок заданий, последний коммит |

`*` — обязательный аргумент.

## Регистрация инструмента

Инструмент — это запись с именем, описанием для модели и JSON Schema аргументов.
Схема и есть контракт: по ней модель понимает, что передавать.

```python
{
    "name": "git_log",
    "description": ("История коммитов репозитория Advent AI Challenge. "
                    "Полезно, чтобы узнать, что и когда делалось в проекте."),
    "inputSchema": {
        "type": "object",
        "properties": {
            "limit": {"type": "integer", "description": "Сколько коммитов вернуть",
                      "minimum": 1, "maximum": 50, "default": 10},
            "grep": {"type": "string",
                     "description": "Искать подстроку в тексте сообщений коммитов"},
            "path": {"type": "string",
                     "description": "Ограничить историю папкой или файлом"},
        },
        "required": [],
    },
}
```

Возврат результата — в формате MCP: список блоков контента плюс признак ошибки.
Ошибка инструмента (неверный аргумент) — это не ошибка протокола, а обычный ответ
с `isError: true`.

## Как инструмент попадает к агенту

```
агент → tools.py → mcp_client.py → git_server.py → git
         ↑ перевод схемы MCP        ↑ JSON-RPC по stdio
           в формат function calling
```

`tools.py` берёт у сервера `tools/list` и переводит записи в формат function calling,
который понимают DeepSeek и Groq. Перевод тривиален: `inputSchema` из MCP кладётся
в `parameters` функции как есть — это один и тот же JSON Schema.

Дальше в `agent.py` работает цикл: модель отвечает не текстом, а списком `tool_calls`;
агент выполняет их через `tools/call`, кладёт результаты в диалог ролью `tool`
и спрашивает снова — пока не получит обычный ответ или не кончатся круги
(`max_tool_rounds`, по умолчанию 3). На последнем круге инструменты убираются,
чтобы модель обязана была ответить текстом.

## Результат: агент вызывает инструмент и использует ответ

Пять вопросов, эталоны для проверки берутся **прямо из git**, а не из головы.

| Режим | Верных ответов | Вызовов инструментов | Токенов |
|---|---:|---:|---:|
| без инструментов | 0 из 5 | 0 | 1 457 |
| с инструментами | 4 из 5 | 4 | 9 206 |

Без инструментов агент повёл себя достойно — не выдумывал, а честно отвечал
«не могу ответить: нет доступа к репозиторию». С инструментами он называет число
коммитов, хеш последнего, дату задания 14 и папку, где впервые встретилось
`inputSchema`.

Многошаговый обмен на живом вопросе:

```
вы → Что было сделано в задании 14 и какие файлы оно добавило?
  🔧 круг 1: git_log({'path': '14-invariants', 'limit': 20})
       → 9d40005 · 2026-09-17 · Задание 14: инварианты проекта
  🔧 круг 1: git_summary({})
       → Коммитов: 18 · Папок заданий: 16
  🔧 круг 2: git_show({'ref': '9d40005'})
       → 9d40005 · alexei-gaidel · 2026-09-17 · список изменённых файлов
агент ← Коммит 9d40005, 17.09.2026, автор alexei-gaidel: «Задание 14: инварианты
        проекта». Добавлена папка 14-invariants целиком: agent.py, invariants.py…
```

Модель сама решила сделать два круга: сначала нашла коммит по папке, затем запросила
его подробности по хешу, полученному из первого вызова.

## Честный промах

Один вопрос из пяти — «сколько в репозитории папок с заданиями» — агент ответил
**не вызвав инструмент вовсе** и ошибся: сказал 18 вместо 16. При том что
`git_summary` возвращает строку «Папок заданий: 16» и одного вызова хватило бы.

Вывод неприятный, но важный: **наличие инструмента не гарантирует, что модель им
воспользуется.** Инструменты дают возможность, а не дисциплину. Лечится тем же, чем
в заданиях 14 и 15 — явным правилом в системном промпте («факты о репозитории бери
только из инструментов, не отвечай по памяти») или проверкой ответа после генерации.

## Безопасность

Сервер только читает и никогда не меняет репозиторий. Команды собираются **списком
аргументов, без оболочки**, поэтому подставить лишнее невозможно; ссылки на коммиты
дополнительно проверяются шаблоном, а пути не выпускаются за пределы репозитория:

```
→ git_show {"ref": "HEAD; rm -rf /"}
  отказ: ref выглядит подозрительно: допустимы хеш, HEAD~N, ветка, тег
```

Это не паранойя: аргументы инструмента приходят от языковой модели, то есть из
ненадёжного источника по определению.

## Выводы

- **MCP и function calling стыкуются без переходника.** `inputSchema` из MCP
  ложится в `parameters` функции как есть — это один и тот же JSON Schema.
- **Описание инструмента важнее его кода.** `git_log` — четыре строки вызова `git`,
  но именно описание и схема решают, позовёт ли его модель и с какими аргументами.
- **Инструменты меняют характер ошибок.** Без них агент отказывается отвечать,
  с ними — отвечает фактами, но может полениться и ответить по памяти. Второе опаснее:
  такой ответ выглядит уверенно.
- **Цена доступа к фактам — токены.** 9 206 против 1 457: каждый вызов возвращает
  текст, который едет в следующий запрос целиком. Инструмент, возвращающий много,
  стоит дорого.
