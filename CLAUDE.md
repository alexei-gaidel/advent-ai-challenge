# Advent AI Challenge — как делается новый день

Инструкция для сессии Claude Code, которая подхватывает проект с нуля. Челлендж
ежедневный: каждый день приходит текстом задание, к вечеру должны быть код,
README с реальными цифрами и запушенный коммит. Формат сдачи — видео + код,
поэтому наглядность важнее объёма.

## Репозиторий

- GitHub: https://github.com/alexei-gaidel/advent-ai-challenge (публичный)
- Локально: `/Users/g.a.s./advent AI challenge`, ветка `main`, пушим сразу
- Одно задание — одна папка `NN-короткое-описание` (`13-task-state`), внутри код
  и свой `README.md`
- Корневой `README.md` — таблица-оглавление, новая строка добавляется в том же коммите
- Дни могут пропускаться (08 нет) — нумерация идёт по заданию, а не по порядку папок

## Жёсткие правила

1. **Только стандартная библиотека Python.** Никакого pip, `requirements.txt` нет.
   HTTP — `urllib.request`, сервер — `http.server`, база — `sqlite3`, замеры —
   `difflib`, графика — рукописный SVG. Если очень нужен пакет — сначала спросить.
2. **Ключи только в корневом `.env`** (`DEEPSEEK_API_KEY`, `GROQ_API_KEY`).
   Он в `.gitignore`. Скрипты ищут его вверх по дереву через `find_env_file()`,
   поэтому запускаются из любой папки. Ключи не печатать в ответах.
3. **Локальные данные в гит не уходят.** Для каждой новой папки дописать в `.gitignore`:
   `NN-название/agents.db*` и `NN-название/custom_roles.json`.
4. **Порт = 8000 + номер дня** (`13-task-state` → 8013). Никогда не гасить серверы
   через `pkill -f web.py` — так убивается и тот, что запустил пользователь.
   Запускать в фоне с сохранением PID и убивать по нему.
5. **Цифры в README — только из реального прогона.** Ничего не додумывать, не
   округлять в свою пользу и не прятать неудобные результаты.

## Наследование кода

Каждый день — самостоятельная копия: папка запускается независимо, прошлые дни не
трогаем. Новый день начинается с копирования предыдущего «агентского» дня:

```
providers.py   два провайдера (DeepSeek, Groq), единый call(), тарифы — копируется как есть
toon.py        компактный формат данных для промпта — копируется как есть
storage.py     SQLite: агенты, сообщения, слои памяти, задача
memory.py      три слоя памяти и роутер
profiles.py    профили пользователя
taskstate.py   конечный автомат задачи
agent.py       класс Agent: вся логика запроса-ответа
web.py         тонкий сервер + страница, логики не содержит
make_cast.py   генератор demo.svg
```

Из копии **вычищается всё, что уводит от темы дня**. Пример: в дне 10 выброшена
суммаризация дня 9, в дне 11 — ветки и стратегии дня 10. Лучше меньше кнопок, чем
демонстрация, в которой не видно сути задания.

Архитектурная граница, которую нельзя ломать: **`web.py` не собирает `messages`,
не знает URL провайдеров и не разбирает их ответы.** Он вызывает методы агента и
рисует результат. Логика дня живёт отдельным модулем (`memory.py`, `taskstate.py`).

## Порядок работы над днём

1. **Прочитать задание и проверить, не сделано ли уже.** Пользователь иногда пишет
   «если уже есть — ничего не делаем». Проверять грепом по коду, а не по памяти.
2. **Задать вопросы до кода** через `AskUserQuestion` — только там, где ответ меняет
   архитектуру: кто принимает решения (LLM или пользователь), где хранить, какой набор
   состояний, что демонстрировать. Рутинные развилки решать самому.
3. **План** (`EnterPlanMode`) — если день большой: новые таблицы, новые модули, смена
   архитектуры. Для добавления пары ролей план не нужен.
4. **Код**: хранилище → логика отдельным модулем → агент → интерфейс. После каждого
   куска — быстрая проверка в python, не дожидаясь конца.
5. **Скрипт-демонстрация** — обязательная часть дня, называется по теме
   (`task_demo.py`, `compare_strategies.py`, `memory_demo.py`). Он прогоняет сценарий
   на живом API, печатает таблицу и служит доказательством. Запускать в фоне
   (`run_in_background`), длинные прогоны — 3–10 минут.
6. **Каст** `python3 make_cast.py` → `demo.svg`: анимированный SVG-каст реального
   прогона, до 60 секунд, встраивается в README. Настоящее видео на этой машине снять
   нельзя — нет ffmpeg и ImageMagick, а `screencapture` требует разрешения Screen
   Recording, которое даёт только пользователь. Это стоит проговаривать честно.
7. **README дня** по устоявшейся структуре: условие задания → запуск → как устроено
   (со схемой или SQL) → результаты прогона таблицей → встроенный `demo.svg` → выводы
   с честными оговорками, где приём не работает.
8. **Проверки перед коммитом** (все выполнять, не «на глаз»):
   - `python3 web.py` поднимается, `GET /` отдаёт 200, плейсхолдеры подставлены;
   - битый payload возвращает JSON с ошибкой, а не рвёт соединение;
   - `git status --short` — базы и `custom_roles.json` не в индексе;
   - `git log --all -p | grep -cE "gsk_|sk-"` после пуша даёт 0.
9. **Коммит и пуш.** Сообщение: первая строка `Задание NN: суть`, дальше 2–4 строки
   что именно сделано, в конце `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

## Грабли, на которые уже наступали

| Симптом | Причина и лечение |
|---|---|
| `403 error code 1010` от Groq | Cloudflare банит `Python-urllib`. Передавать свой `User-Agent` в заголовках |
| Таймаут не ловится `except URLError` | `TimeoutError` не наследник `URLError` — ловить отдельно |
| В браузере `TypeError: Load failed`, причины не видно | Разбор payload стоял до `try`. Весь `do_POST` под `try` + `traceback.print_exc()` в консоль сервера |
| `KeyError: '"layer"'` в промпте | `str.format()` съедает фигурные скобки JSON-примера. Подставлять через `.replace("<<TEXT>>", …)` |
| После перезапуска новый агент затирает старого | Счётчик id должен продолжаться с максимума в базе (`max_agent_number() + 1`) |
| События задачи дублируются в базе | Поднятые из базы помечать `saved = True` |
| Пустой `content` у рассуждающей модели | `gpt-oss` тратит бюджет на скрытые reasoning-токены; давать запас `max_tokens`, читать `message.reasoning` |
| Проверка ответа подстрокой врёт | В бессвязном тексте случайно нашлась нужная цифра. Называть метку честно («эталон найден», не «верно») и дублировать LLM-судьёй |
| Судья подсуживает | Ответы обезличивать и перемешивать; судью брать у провайдера, который не участвует в сравнении |

## Что делает день хорошим

Задание почти всегда просит «сравнить» или «проверить». Ценность не в том, что приём
заработал, а в **честном замере**: сколько токенов, сколько верных ответов, что
сломалось. Лучшие дни получались там, где результат оказался неожиданным и это попало
в README:

- сжатие истории (день 9) на коротком диалоге ушло в минус на 312 токенов;
- TOON экономит 39–48% токенов, но DeepSeek читает его с ошибками, а модели Groq нет;
- `temperature=0` не дал дословной повторяемости;
- 120B-модель оказалась в пять раз дешевле 27B — цена не про размер;
- Sticky Facts потратил на обслуживание больше токенов, чем сам диалог.

Если прогон дал странный результат — перепроверить (повторить 3 раза, зафиксировать
`temperature=0`), а потом писать как есть. Один прогон выводом не считается.

## Общение с пользователем

По-русски. Коротко: что сделано, ссылка на папку, команда запуска, таблица цифр,
1–2 действительно интересных наблюдения и что показать на видео. Свои ошибки называть
прямо и без самобичевания — их находка обычно и есть самое полезное в дне.
