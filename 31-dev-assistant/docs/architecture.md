# Архитектура проекта Advent AI Challenge

Документ для разработчика, который впервые открыл репозиторий. Правила работы над днём —
в `CLAUDE.md`, описание каждого дня — в `NN-*/README.md`, справочники, собранные из кода, —
`docs/schemas.md` (таблицы SQLite) и `docs/mcp-api.md` (MCP-инструменты и порты).

## Раскладка репозитория

```
advent AI challenge/
├── .env                 ключи DEEPSEEK_API_KEY и GROQ_API_KEY (в .gitignore)
├── .env.example         шаблон .env
├── .github/workflows/   GitHub Actions дней 18 и 19 (расписание, коммиты-наблюдения)
├── CLAUDE.md            как делается новый день: правила, порядок, грабли
├── README.md            оглавление: таблица всех дней
└── NN-название/         один день = одна самостоятельная папка
    ├── README.md        условие, запуск, устройство, результаты, выводы
    ├── *.py             код дня, только стандартная библиотека
    ├── *_demo.py        скрипт-доказательство на живом API
    ├── make_cast.py     генератор demo.svg
    └── demo.svg         анимированный каст прогона
```

Номер папки — номер задания, а не порядковый: дня 08 и дня 27 в репозитории нет.

## Линии развития

Дни не зависят друг от друга при запуске, но код переходит из дня в день копированием.

| Линия | Дни | Что накапливается |
|---|---|---|
| Запрос к LLM | 01–05 | `urllib`-запрос, формат ответа, температура, сравнение моделей |
| Агент | 06–15 | класс `Agent`, история в SQLite, сжатие, стратегии контекста, слои памяти, профили, конечный автомат задачи, инварианты, этапы |
| MCP | 16–20 | свой клиент MCP на stdlib, свои серверы (git, рынок, пайплайн, погода/деньги/заметки), оркестрация |
| RAG | 21–25 | чанкинг, эмбеддинги bge-m3, индекс в SQLite, порог и реранк, цитаты, чат с памятью |
| Локальные модели | 26–30 | Ollama на этом Mac, локальный RAG, оптимизация, приватный сервис-шлюз |
| Ассистент разработчика | 31 | RAG по документации проекта + MCP к git-репозиторию, команда `/help` |

## Типовые модули агентского дня

| Файл | Ответственность |
|---|---|
| `providers.py` | единый `call()` для DeepSeek и Groq: URL, ключ, тарифы, разбор ответа, `tool_calls` |
| `toon.py` | компактный формат данных для промпта |
| `storage.py` | SQLite: агенты, сообщения, слои памяти, состояние задачи |
| `memory.py`, `profiles.py`, `taskstate.py`, `invariants.py` | логика конкретного дня отдельным модулем |
| `agent.py` | класс `Agent`: сборка `messages`, вызов модели, цикл инструментов |
| `web.py` | тонкий HTTP-сервер на `http.server` и HTML-страница |
| `mcp_client.py` | клиент MCP: транспорты stdio и Streamable HTTP, `initialize` → `tools/list` → `tools/call` |
| `tools.py` | мост MCP ↔ function calling (`ToolBridge`) |
| `embeddings.py` | векторы bge-m3 через локальную Ollama, L2-нормировка |
| `index.py` | чанки и векторы в SQLite, поиск косинусом |

Граница, которую не ломают: `web.py` не собирает `messages`, не знает URL провайдеров и
не разбирает их ответы — только вызывает методы агента и рисует результат.

## Внешние зависимости

- **DeepSeek API** (`deepseek-chat`, `deepseek-reasoner`) — основная модель и судья.
- **Groq API** (gpt-oss-20b/120b, qwen, allam) — сравнение моделей и независимый судья.
- **Ollama** на `localhost:11434` — эмбеддинги `bge-m3` (дни 21–25, 28, 29, 31) и локальные
  модели `qwen2.5:3b/7b` (дни 26–30).
- **git** — MCP-серверы дней 17 и 31 читают репозиторий командами git без оболочки.

Пакетов из pip нет ни в одном дне: HTTP — `urllib.request`, сервер — `http.server`,
база — `sqlite3`, графика — рукописный SVG.

## Как устроен ассистент дня 31

```
вопрос → /help
   ├─ MCP project_server.py → git_branch (всегда, кодом)
   ├─ RAG: bge-m3(вопрос) · векторы чанков README/CLAUDE.md/docs → топ-6
   └─ DeepSeek с function calling: при нужде вызывает git_status, git_files,
      git_diff, git_log, read_file через тот же MCP → ответ со ссылками на источники
```

Индекс (`index.db`) пересобирается командой `python3 index.py`; по отпечатку
корпуса ассистент сам замечает, что документы изменились, и предупреждает.
