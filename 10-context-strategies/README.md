# 10 — Управление контекстом: три стратегии (без summary)

**Задание:** реализовать три стратегии управления контекстом с переключателем —
Sliding Window (только последние N сообщений), Sticky Facts (блок ключ-значение с важными
данными плюс последние N, обновляемый после каждого сообщения пользователя) и Branching
(чекпоинт, две ветки от одного места, независимое продолжение и переключение). Прогнать
один сценарий на каждой и сравнить качество, стабильность, расход токенов и удобство.

Сжатия истории здесь нет намеренно — это было заданием дня 9.

## Запуск

```bash
cd 10-context-strategies
python3 web.py                          # откроется http://localhost:8010
python3 compare_strategies.py           # прогон сценария на всех трёх стратегиях
python3 compare_strategies.py --branching   # только демонстрация веток

```

## Три стратегии

| Стратегия | Что уходит в модель | Состояние в базе |
|---|---|---|
| **Sliding Window** | system + последние `keep_last` сообщений | только `messages` |
| **Sticky Facts** | system + карточка фактов + последние `keep_last` | `messages` + таблица `facts` (ключ-значение) |
| **Branching** | system + **вся** цепочка активной ветки | `messages.branch_id` + `branches` + `checkpoints` |

Переключаются на лету кнопками в панели. Карточка фактов обновляется **отдельным вызовом
LLM** после каждой реплики пользователя: модель возвращает JSON вида
`{"цель": "…", "бюджет": "…"}`, он сливается в таблицу. Расход на эти вызовы считается
отдельно — иначе сравнение было бы нечестным.

Ветка хранится не копией истории, а ссылкой на родителя:

```python
def chain(self, branch_id):
    """Полный путь ветки: унаследованный префикс родителя плюс свои реплики."""
    branch = self.branches[branch_id]
    if branch["parent_id"] is None:
        return list(self.messages[branch_id])
    return self.chain(branch["parent_id"])[:branch["fork_at"]] + list(self.messages[branch_id])
```

`fork_at` — сколько сообщений родителя унаследовано. Поэтому ветки дешёвые (ничего не
дублируется) и изолированные: реплики соседней ветки в цепочку не попадают физически.

## Сценарий и результаты

Сценарий «собираем ТЗ» — 18 реплик: пять с требованиями (цель, бюджет и срок, стек,
ограничение по эквайрингу, предпочтения по дизайну), восемь обсуждающих, и пять
контрольных вопросов ровно про требования из начала. Окно `keep_last=6`, модель
`deepseek-chat`, `temperature=0` — к моменту контрольных вопросов требования давно
вышли за пределы окна.

| Стратегия | Токенов запроса | Накладные | Всего | Помнит требования | Секунд |
|---|---:|---:|---:|---:|---:|
| Sliding Window | 4 151 | 0 | 5 024 | **0 из 5** | 25.8 |
| Sticky Facts | 6 884 | 7 851 | 15 757 | 5 из 5 | 59.3 |
| Branching (вся цепочка) | 15 174 | 0 | 16 244 | 5 из 5 | 29.0 |

**Sliding Window провалил все пять контрольных вопросов.** Не «ответил неточно» — он
честно сообщил, что таких требований не было:

> В ТЗ предпочтений по дизайну нет — назови стиль, брендбук и референсы, и зафиксируем.

Это ровно та ситуация, ради которой существуют остальные стратегии: окно дешёвое и
предсказуемое, но всё, что вышло за его край, для агента не существует.

**Sticky Facts вытянул 5 из 5**, имея то же окно в шесть сообщений. Карточка после
прогона:

```
цель: мобильное приложение для аренды велосипедов в Казани
сроки: три месяца, запуск 1 декабря
бюджет: 2,5 млн рублей
стек: Flutter на фронте, Python и FastAPI на бэке, база PostgreSQL
ограничения: эквайринг только Тинькофф, других провайдеров подключать нельзя
предпочтения: тёмная тема по умолчанию, минимализм, без анимаций
```

Но ценой: **накладные расходы (7 851 токен) превысили сам диалог** (6 884). Обновление
карточки после каждой реплики — это второй вызов LLM на каждом шаге, отсюда же и
вдвое большее время (59 секунд против 26).

**Branching дал те же 5 из 5** просто потому, что отправляет всю цепочку целиком —
он вообще не про экономию, а про изоляцию альтернатив.

## Ветвление: две ветки от одного чекпоинта

Проверка сделана на однозначном факте — кодовом имени проекта. С архитектурными
решениями модель начинает спорить и предлагать своё, и это мешает увидеть суть.

```
ветка «Тюльпан» (a1-b1): «Тюльпан».
    назвал своё имя: True · имени соседней ветки в контексте нет: True
ветка «Кедр» (a1-b2): Кедр.
    назвал своё имя: True · имени соседней ветки в контексте нет: True

веток: 3, общий префикс: 6 сообщений
```

Изоляция проверяется не «на глаз», а структурно: в собранной цепочке каждой ветки
имени из соседней нет физически.

## Сравнение по четырём осям

| | Sliding Window | Sticky Facts | Branching |
|---|---|---|---|
| **Качество ответа** | ответы связные, но по старым темам бесполезные | лучшее: факты всегда под рукой, ответы точные и короткие | точное, но многословное — в контексте весь разговор |
| **Стабильность** | 0 из 5, теряет всё за краем окна | 5 из 5, пока факт попал в карточку | 5 из 5, ничего не теряет по построению |
| **Расход токенов** | самый дешёвый, размер запроса постоянный | запрос ограничен, но +100% вызовов сверху | растёт линейно с длиной ветки |
| **Удобство** | нечего настраивать, но агент «глупеет» незаметно | карточку видно и можно править — самый прозрачный вариант | незаменим для сравнения альтернатив, но требует ручного управления |

## Вывод

Стратегии не конкурируют, а решают разные задачи:

- **Sliding Window** годится для коротких сессий и болтовни, где старое действительно
  не нужно. Его главная опасность — агент не сообщает, что забыл: он уверенно отвечает
  на основе обрывка контекста.
- **Sticky Facts** — рабочий вариант для длинных содержательных диалогов вроде сбора ТЗ.
  На нашем сценарии из 18 реплик он ещё не окупился (накладные съели экономию), но его
  запрос не растёт с длиной разговора, тогда как у полной истории растёт линейно —
  чем дольше диалог, тем сильнее перевес в его пользу. Ровно та же арифметика, что
  и у сжатия в дне 9.
- **Branching** — не про экономию вообще, а про «а что если»: сравнить два решения от
  одной точки, не пересобирая контекст и не пачкая одну ветку решениями другой.

Практический вывод: Sticky Facts и Branching **сочетаются** — карточка фактов держит
требования, а ветки позволяют щупать альтернативы. Sliding Window разумно оставить
как дешёвый режим по умолчанию для коротких разговоров.
